# 页面跳转后会发生什么

用户打开、替换、返回或重启页面时，页面栈决定哪一页显示、哪一页隐藏，以及返回时去哪一页。

## 正常流程

| API | 用户会看到什么 | 原页面怎样处理 |
| --- | --- | --- |
| `navigateTo` | 打开新页面 | 留在返回历史中 |
| `redirectTo` | 用新页面替换当前页 | 被替换页不能返回 |
| `navigateBack` | 回到前面的页面 | 弹出指定数量的页面 |
| `reLaunch` | 打开指定页 | 清空当前历史 |
| `switchTab` | 切换到标签页 | 使用该标签保存的历史 |

运行程序先检查目标属于当前项目，再更新页面栈。成功后，当前页面收到隐藏通知，新页面收到加载和显示通知。返回时顺序相反。

## 关键规则

每个 TabBar 标签有自己的页面历史。普通页面不能变成标签页根页面。异步打开页面返回后，还要确认用户没有已经切换项目或继续导航。

## 失败时先查什么

- 用户没有跳转：检查目标路径是否存在于当前项目。
- 返回后页面状态不对：检查页面栈是否只更新了一次。
- 自动化读取旧页面：检查测试读取的是当前项目运行。

相关代码在 `src/shared/simulator-route.ts`、`packages/dimina-electron-runtime/src/simulator-ui/page-stack-controller.ts` 和 `miniapp-frame.tsx`。标签页规则见[TabBar](./tab-bar.md)。
